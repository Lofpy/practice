# PoppyPractice の構成と動作確認

Minecraft 1.7.10 / 1.8.x クライアント、WindSpigot 1.8.8、Java 8互換のプラグインを対象とします。サーバー起動はJava 17を選ぶ既存の `run.bat` / `start.ps1` を使用します。

## 責務の分割

| 領域 | 主なクラス | 役割 |
| --- | --- | --- |
| メニュー共通 | `MenuHolder`, `MenuNavigation`, `LobbyAction` | 画面と操作を型・スロットで識別し、画面遷移を次tickに実行 |
| キット選択 | `KitSelectionMenu` | Queue・Kit Editor・Bot戦で左詰めの選択画面を共有 |
| Bot設定 | `BotSettingsMenu`, `BotSettingCategory`, `BotSetting` | 選択キットを画面ごとに保持し、共通設定を基本・移動・照準・攻撃・回復の行に分類 |
| キット配置 | `KitLayoutService` | スタック単位の入れ替え、配置の検証・保存、編集中画面の終了処理 |
| 試合結果 | `MatchResultService`, `MatchResultView`, `MatchResultSelection` | 保管・閲覧許可、表示、閲覧者と結果に紐づくナビゲーションを分離 |
| スコアボード | `MatchScoreboardService`, `PracticeSidebar` | 更新スケジュールと表示を分離し、同じボードを再利用 |
| アリーナ | `ArenaManager`, `ArenaRegistry` | 設定読込と予約管理を分離 |
| 対人試合 | `MatchService`, `MatchCompletion`, `MatchManager`, `Match` | 開始・進行、終了処理、所属情報、状態遷移を分離 |
| Combo戦闘設定 | `ComboConfig`, `ComboCombatService`, `ComboRules` | 独立したKB・無敵時間の適用と復元、試合に基づくパール8秒の判定 |
| 遅延アイテム処理 | `PlayerProfile` のcombat session、各Listener | パール再発射・返却・ポーション補充を発生元の試合に限定 |
| 終了処理 | `CleanupTasks` | Bot・プラグイン終了時、一部の失敗が別リソースの解放を妨げないようにする |
| ReachGuard VL | `ReachViolationPolicy` | 違反種別と加算式を通知・保存・証拠ログで共有 |

## メニューのルール

- タイトル・表示名・loreは表示専用。メニュー操作の識別に使用しません。
- 操作対象は上段インベントリの有効スロットのみです。下段、外側、ドラッグ、数字キーなどによってメニューアイテムを持ち出す操作を受け付けません。
- 画面を開閉する操作はInventoryClickEventの完了後に実行します。実行時にオンライン状態と元の画面が開いていることを再確認します。
- Bot戦はキット選択 → 設定 → 明示的な開始の順に進みます。閲覧・戻る・閉じるではQueueを解除しません。設定値は共通ですが、選択キットは各画面に保持し、他プレイヤーの変更・再描画で切り替えません。
- Boxingの最大体力・回復設定はグレー表示して操作を拒否し、保存値は保持します。全初期化だけは両キット共通の全設定を対象とし、Shift＋左クリックを必要とします。
- キットのプレビューではスタックの数・種類を変更できません。閉じる時にカーソルを戻し、元のキットと一致する配置だけを保存します。
- 結果画面は保存されたスナップショットを表示し、閲覧者・対象の試合・スロットが一致する操作だけを受け付けます。
- 結果統計は英語の3群です。Status（HP・Hunger）、Combat Statistics（Hits・Criticals・Guards）、Potion Statistics（残数・回復量・正確性・ミス・Overheal・相手の回復量）。残ポーション0個は空瓶で表します。

## 試合と予約のルール

アリーナの予約を取得した後は、開始処理が成功しても失敗しても試合サービスが予約を管理します。Queueが失敗後に二重解放することはありません。

使用中アリーナは設定を再読み込みしても予約・スポーン位置を保持します。変更された定義、無効化、削除は試合が終了して解放された時点で反映します。

対人試合の終了処理は一度だけ実行します。結果の取得・表示に失敗しても、所属解除・両者のロビー復帰・アリーナ解放・FINISHEDへの移行を続行します。開始・カウントダウンの遅延処理は、現在も同じ試合に所属していることを確認します。

アイテムの遅延処理はプレイヤーのprofileとcombat sessionを照合します。STARTINGからFIGHTINGへの移行は同じsessionですが、ロビーへ戻る・次の試合を開始する・再接続する操作では古い処理を無効にします。

ComboのKBは両参加者それぞれに生成した未登録プロファイルで、WindSpigotの共通プロファイルには書き込みません。
アリーナ転送・装備適用後に専用KBと無敵時間を適用し、終了・切断・開始失敗・停止時に元の値を復元します。
復元はロビーのインベントリ処理より先に行い、ロビーへのワールド移動が無敵時間を上書きした場合も元の値へ戻します。
Comboのパール8秒はロビーの選択キットではなく実際の試合のキットで判定するため、次のNoDebuff戦へ残りません。

クライアントでの確認項目:

1. QueueとKit Editorの選択肢が左詰めで、説明・Closeが下段にあること。
2. キット編集中に剣やパールを移動し、カーソルにアイテムを持ったまま閉じても配置が保存され、個数が変わらないこと。
3. Bot Fightと`/bot`からキット選択 → 分類別Bot Settingsへ進み、キット選択だけでは試合が始まらないこと。戻るボタンで選び直せること。Boxingの体力・回復設定は操作できないこと。共有値の変更で別プレイヤーの画面も更新され、その人の選択キットは変わらないこと。全初期化がShift＋左クリックでだけ動くこと。
4. 結果チャットの名前・左右矢印で両者の情報を確認し、下段の自分のアイテムをクリックしても画面が遷移しないこと。
5. 対人／Bot試合の途中で `/practice reload` を実行しても、使用中のアリーナに別の試合が入らないこと。
6. ロビーへ戻った直後に古いパールが発射されたり、前の試合の補充がロビーの持ち物へ混入しないこと。

既存のKB・Bot戦闘設定、パール16秒、Pingの2tick取得、ReachGuardの3.000マス境界はこのリファクタリングで変更しません。実際に使用される値は既存の本番configを優先します。
