# 認定戦・ELO・Duel・キルエフェクト

## プレイヤー向け

PvPサーバーのロビーには、左からQueue、Kit Editor、Bot Fight、Certification Queue、Settingsを配置します。
認定戦の入口はホットバーの左から7番目にある経験値ボトルです。Queue画面の右下にも同じ
「Certification Queue」ボタンがあり、Kit別の認定進捗を表示します。クリックしてKitを選択すると
そのKitの固定Bot認定戦を開始します。通常のRanked Queueに参加したまま認定戦へは移行しません。
独立した接続ロビーにいる場合は、先に`/pvp`でPvPサーバーへ移動してください。

| 機能 | 操作 |
| --- | --- |
| 認定戦 | Certification Queueアイテム／Queue画面右下の同名ボタン、または`/tier`でKitを選択。`/tier nodebuff`、`/tier boxing`、`/tier combo`でも開始できます。 |
| レート確認 | `/elo`、または`/elo <kit>`。PvPロビーのスコアボードとQueue画面にも表示します。 |
| Ranked | 従来のQueueアイテム。選んだKitの認定を3戦完了すると参加可能です。 |
| 通常Bot練習 | 従来のBot Fight、`/bot`。認定回数・ELOには影響しません。 |
| Duel | `/duel <プレイヤー名>`でKit選択、または`/duel <プレイヤー名> <kit>`で招待します。 |
| Duel承諾・拒否 | チャットのAccept / Deny、または`/duel accept <名前>`、`/duel deny <名前>`。 |
| エフェクト | Settingsアイテム、または`/settings`。雷（初期設定）、爆発、レッドストーンから選択します。 |

NoDebuff・Boxing・Comboの**認定回数とELOはそれぞれ独立**しています。
例えばBoxingの認定を3戦終えても、NoDebuffのQueueは解放されません。
認定戦は勝敗を問わず最後まで対戦すれば1戦として数えます。切断・途中退出・管理者の強制終了・
サーバー停止・カウントダウン中の終了は数えません。設定を変更できる通常Bot戦も数えません。
認定完了後は再認定で初期レートを引き直すことはできません。

## 採点モデル v1

固定されたHard相当のBot設定を使用します。プレイヤーが通常Bot設定GUIで変更した値は使いません。
認定専用の移動は、横入力を0.18（通常の初期値0.828の約22%）に抑え、前後の間合い調整を優先します。
約2.35～2.65ブロックを目安に、接近しすぎれば後退し、相手が離れれば前進して追撃します。
相対的な水平速度から最大2tick先の距離変化を予測します（補正幅は±0.45ブロックまで）。
有効ヒット後は既存の1tickのW離しを使い、8tickの間は横入力を止めてコンボの間合いを維持します。
毎ヒット後に固定時間逃げる動作やジャンプは追加しません。被弾中は前入力でKBに対抗します。
通常BotのGUI設定・移動、KB・リーチ・CPS・回復動作、Kit別の採点式は変更していません。
各試合を0～100点で評価し、最初の3試合の平均点から初期ELOを決めます。

| Kit | ヒット比率 | 勝敗 | 残りHP | ポーション精度 |
| --- | ---: | ---: | ---: | ---: |
| NoDebuff | 50% | 20% | 10% | 20% |
| Boxing | 80% | 20% | — | — |
| Combo | 65% | 25% | 10% | — |

- ヒット比率：自分のヒット数 ÷ 両者の合計ヒット数。両者0ヒットの場合は0。
- 勝敗：勝ち100%、負け0%。
- 残りHP：試合終了時HP ÷ 20。敗北者のHPは0として扱います。
- ポーション精度：実際に回復したHP ÷（投げた回復ポーション数 × 8）。0～100%に制限します。
- NoDebuffでポーションを1個も使用していない場合、精度の項目を除き、残りの重みを合計100%に正規化します。

`初期ELO = 1500 + 3 × 3試合の平均点`、範囲は1500.000～1800.000です。
これは当サーバーの固定Botを基準にしたローカル評価であり、外部コミュニティのTierと同等とは限りません。
生のヒット数・クリティカル数・ガード数・回復・ミス・オーバーヒール・相手への回復量なども記録し、
後から評価根拠を確認できます。Bot自体のロジックや共通KBを変更すると評価の比較条件も変わります。

## Ranked ELO

- K=32、期待勝率のスケールは通常の400。
- 勝者の増加量は`32 × (1 − 勝者の期待勝率)`、敗者は原則として同額を失います。
- 同レートなら勝者+16.000、敗者−16.000。
- 小数点以下3桁で保存・表示します。
- 敗者のレートが1400.000未満になる場合は1400.000で止めます。この場合だけ増減がゼロサムになりません。
- マッチ可能なのは同じKitでELO差が100.000以下の組み合わせです。待ち時間による条件緩和はありません。
- 待機列の先頭に相手がいない場合も、後ろに成立する組み合わせがあればマッチします。
- 試合開始後の切断は敗北としてELOが変動します。開始前の中断・管理者の強制終了・サーバー停止では変動しません。

## Duelと試合終了

Duelは両者がPvPロビーで待機中（Queue参加中でないこと）に承諾できます。
認定は不要で、終了理由にかかわらずELOは変動しません。招待は60秒で失効し、送信間隔は3秒、
同時に保持する送信済み招待は1人につき1件です。承諾時にアリーナがなければ、失効前に再度承諾できます。

通常の決着後は、倒された位置に勝者が選択したキルエフェクトを表示します。Bot勝利時は初期設定の雷です。
爆発・雷は演出のみで、ダメージ・火災・ブロック破壊は起きません。
60tick（通常3秒）の間は移動・攻撃・アイテム使用を停止し、アリーナの予約も維持します。
その後、両者をPvPロビーへ戻します。切断・強制終了・停止時は安全のため即時に後処理します。
試合結果のインベントリ表示・チャットの名前クリックは従来どおり利用できます。

## 保存先と運用

### 管理者による認定リセット

PvPサーバーのゲーム内、またはサーバーコンソールから`/tierreset`を使用できます。
権限は`practice.admin`（初期設定ではOPのみ）です。コマンド導入後のリセットに再起動は不要です。

| コマンド | 対象（この段階ではプレビューのみ） |
| --- | --- |
| `/tierreset <名前またはUUID>` | 指定プレイヤーの全Kit |
| `/tierreset <名前またはUUID> nodebuff` | 指定プレイヤーのNoDebuffのみ（`boxing`・`combo`も可） |
| `/tierreset all` | 全プレイヤーの全Kit |
| `/tierreset all boxing` | 全プレイヤーのBoxingのみ |
| `/tierreset confirm <確認コード>` | 同じ管理者が60秒以内に確認し、バックアップ後に実行 |
| `/tierreset cancel` | 自分の確認待ち操作を取り消す |

削除されるのは対象Kitの認定点数・認定回数・資格・**ELO（ランク戦で変動した分も含む）**です。
対象は0/3に戻り、3戦で新しい初期ELOが決まります。指定していないプレイヤーとKitのELOは変更しません。
過去の試合IDは二重計上防止用に保持するため、古い試合の再送信で認定やELOを復活させることはできません。
個人のKit配置、エフェクト設定、通常Bot設定、KB、ワールドは変更しません。

名前はオンラインまたはサーバーに保存済みのプレイヤーだけを解決し、外部への名前検索は行いません。
同名の候補が曖昧な場合はUUIDを指定してください。
対象がQueue・カウントダウン・試合・試合終了待機に入っている場合は実行しません。
Kitを限定していても、対象プレイヤーはほかのKitを含めてQueueや試合から退出してください。
確認前に新しい結果が保存された場合も再プレビューが必要です。

バックアップはプラグインの`backups/certification-reset-*`に作成し、実行後に場所を表示します。
バックアップにはリセット前の全体台帳と対象の認定評価ファイルが含まれます。
復元はPvPを通常停止してから行い、リセット後の新しい結果がある場合は先に別途退避してください。
全体台帳を復元すると、リセット後に保存されたほかのプレイヤーのレートも巻き戻る点に注意してください。
リセット中に停止・保存障害が発生し`certification-reset.pending`が残った場合は、読み込みを停止して保護します。
PvPを通常停止し、現状を別途保全したうえで、マーカーが指すバックアップの`manifest.yml`とSHA-256を確認してください。
`ratings.yml`全体と、`manifest.yml`の`targets`に記載された評価ディレクトリだけを復元します。
復元と整合性を確認してからマーカーを取り除き、`run.bat`で起動してください。先にマーカーだけを削除しないでください。

### データファイル

- `runtime/plugins/PoppyPractice/ratings.yml`：UUID別・Kit別の認定点数、ELO、処理済み試合ID。
- `runtime/plugins/PoppyPractice/tier-assessments/<UUID>/<kit>/<match UUID>.yml`：認定ごとの評価指標と生の戦績。
- `runtime/plugins/PoppyPractice/cosmetic-preferences.yml`：UUID別のキルエフェクト選択（全Kit共通）。

保存は一時ファイルからのアトミック置換で行います。対人戦の両者のELOは1回の保存で確定し、
同じ試合IDの再処理では二重に変動しません。レート保存失敗はチャット・サーバーログに表示し、
成功したようには表示しません。認定の評価詳細が保存できなければ認定回数も増やしません。
破損したレートファイルは初期化せず、起動時にエラーとして停止します。破損した個人設定ファイルは
そのまま保護し、設定変更を停止します。復旧前にファイルを退避し、バックアップから復元してください。
運用中の手編集は避け、バックアップと変更はPvPサーバー停止中に行ってください。

ELOの範囲・K値・認定数は今回指定された競技ルールとして固定しています。
既存のKit内容・KB・パール設定・独立した接続ロビーの設定は変更しません。
